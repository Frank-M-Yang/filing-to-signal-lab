# 拆股口径修复与同样本迁移审计

## 本轮改动

主管道和公告时间重建适配器现在使用每次事件的 `split_from / split_to`，
只累乘纽约日期边界之前已经发生的拆股。供应商的 `historical_adjustment_factor`
只保留作审计证据，不再用于市场特征换算；缺少单次比例时直接拒绝，不回退到累计因子。

例如两次拆股分别为 1 拆 2、1 拆 3，正确的历史价格因子为 1/6。
将供应商的累计因子 1/6 和 1/3 再次相乘会得到错误的 1/18。
这是用于回归测试的合成例子，不是本轮新发现的真实股票收益。

增加的约束包括：

- 调用方明确声明原始交易口径，构建入口核验供应商请求为 `adjusted=False`。
- 拒绝未知口径、已调整标记、重复行动日期、缺失或非正的单次比例。
- 输出保留原始列、统一单位列和逐行因子；重复传入本工具的调整结果会被拒绝。
- 价格和股数成交量反向换算，检验价格乘成交量不变。
- 后续拆股或累计因子的修改，不改变边界前的换算结果。
- Yahoo 的无拆股代数对照显式标为诊断假设，不因此获得原始行情认证。

仅凭数值无法识别一个刻意移除标记、错误宣称为原始行情的输入。
因此这些检查不能取代供应商请求证据和历史口径审计。

另修正主管道的日期边界：UTC 跨日不等于纽约跨日，统一按纽约公告日期排除当天行情。
这落实的是保守的“公告前一交易日及更早”约定；不能据此断言所有被移除的当天收盘价
在真实公告时都尚不可得。首次公开时间与 SEC 接受时间的差异仍需单独处理。

主管道版本提升为 `validation-market-state-v2-local-split-ratios`，拒绝用旧版本名写入新语义。
旧缓存、旧报告和旧实验配置未覆盖，也没有自动切换下游模型。

## 同样本实测结果

固定沿用旧包的 **227 个事件、48 家公司、13 项市场特征**，不依据结果更换样本。
价格读取按事件前日期过滤；不读取财报后数值行情，不计算策略收益。

| 项目 | 结果 |
| --- | --- |
| 旧版 / 新版特征可用事件 | 175 / 175 |
| 保留的不可用事件 | 52 |
| 特征有数值变化的事件 | 3 |
| 有变化的特征单元格 | 39 |
| 有拆股调整的事件 | 5 |
| 原始拆股记录 / 累计因子与单次比例不相等的记录 | 2 / 0 |
| UTC 与纽约日期不同的事件 | 4 |

当前缓存只有 PANW、EAF 两次相关行动，其累计因子恰好等于单次比例。
因此这次防错修复**没有证明旧样本受到了累计因子错误污染**。

三个数值变化事件全部属于纽约日期边界修复：

| 股票 | 纽约公告日期 | 旧输入最后交易日 | 新输入最后交易日 |
| --- | --- | --- | --- |
| PATH | 2024-12-06 | 2024-12-06 | 2024-12-05 |
| NUS | 2025-05-08 | 2025-05-08 | 2025-05-07 |
| PANW | 2025-11-19 | 2025-11-19 | 2025-11-18 |

第四个跨日事件原本就缺少足够历史，仍保持不可用。
另有 33 条不可用事件的原因文字由 `insufficient_strictly_prior_history` 变为
`missing_issuer_price_history`：诊断读取器在读取数值前先排除了非历史日期，传入空表时
命中了更具体的分支。这不是新增数据损失；可用性和缺失特征均未改变。

另外重放 UFPT、USNA、MBUU 的既有公告时间重建入口：前两例仍可形成市场特征，
MBUU 仍因历史不足而不可用，没有用别的数据源自动填补。三个入口均未打开模型/交易准入。

## 意义与限制

本轮价值是防止以后扩大数据时把股数变化、未来调整或日期换算问题误当成信号。
它不是新的盈利证据，没有重训模型、没有提高收益，也没有解决 ARC 最终兑付证据。

旧主管道的共同交易日选取方式本轮仍保留；严格连续正式交易日完整性、首次公开时点、
供应商当时实际送达时间，不能因这次修复就认定全部通过。

下一步应先把上述剩余输入资格条件统一起来，再冻结可用事件交集，重跑原有模型基线；
不能把新版特征混入旧结果后继续沿用旧结论。
