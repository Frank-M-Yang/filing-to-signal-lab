# 纵向事件扩样设计 v1.1

## 为什么不直接挑“有数据的事件”

当前28个真实收益事件只有11个完整 Level / Delta / Innovation。如果根据当期特征是否
存在来挑事件，会把当前公告内容带入样本选择，并把研究对象悄悄改成“恰好容易解析的
公司”。本轮采用两个用途分离的事件框：

- 代表性母框：保留28家概率样本发行人的全部原始10-Q/10-K，用于展示覆盖缺失；
- 特征密集开发框：只用研究开始前的PIT历史预先确定发行人资格，之后无条件纳入其全部
  filing，用于第一版有足够统计门槛的条件性信号诊断。

开发框估计的是“具有充分历史的毛利率披露发行人”，不是全体美股。两个 estimand 不得
混合报告。

## 冻结选择合同

- 资格截止时间：`2024-10-30T00:00:00Z`；
- 资格要求：截止前至少8个有效 Level、4个有效 Delta、4个标准化样本外 Innovation；
- 当前事件的财务特征、价格覆盖、退市状态和事件收益均不得用于资格；
- 资格通过后，官方交易日历能解析完整窗口的全部原始10-Q/10-K都必须进入；
- 执行窗口仍为公告后第二个交易日开盘进入、持有20个正式交易日、收盘退出；
- 当前或后来 ticker 不得回填历史窗口，新窗口必须重新验证 ticker、FIGI和交易所。

## 冻结结果

- 数据版本：`longitudinal-event-expansion-v1.1-28158673fcdf01d6`；
- 代表性母框：28家、106个事件；
- 特征密集开发框：15家、58个事件；
- Level：57 / 58；
- Delta：53 / 58；
- raw / standardized Innovation：49 / 58；
- 完整共同样本：49 / 58（84.5%）；
- 最低20事件门：预计通过；
- 最低80%覆盖门：预计通过；
- 行情收益门：未通过；
- 信号有效性结论：禁止。

49个完整事件来自15家发行人，事件在公司内部高度聚类。未来即使行情完整，也必须使用
发行人聚类的 bootstrap / 标准误、按时间切分，并报告每家公司影响力；不能把49个事件
当成49个相互独立样本。

## 低成本行情采集设计

58个事件被压缩为15个发行人时间段，每家只计划抓一次整段未调整日线，再按事件切窗，
避免重复请求重叠的20日窗口。每家还需要时间段起终点的历史证券身份、ticker事件、拆股、
分红和退市结果。

- 12家已有足够的历史 ticker 查询证据，可在身份端点复核后抓整段行情；
- ASNS、LEXX、ISPO共12个事件必须先按历史日期用CIK发现当时ticker/FIGI；
- 所有15家在新时间段完成身份连续性、公司行为和退市审计前，收益门保持关闭。

## 复现

```powershell
uv run python -m scripts.build_longitudinal_expansion
uv run streamlit run app.py
```

输出包含发行人资格审计、106事件母框、58事件开发框、28家市场批次计划和106条
事件—批次映射。所有输入通过 readiness、filing catalog、PIT feature、官方日历、证券
行为和Massive reference manifest的SHA-256绑定。
